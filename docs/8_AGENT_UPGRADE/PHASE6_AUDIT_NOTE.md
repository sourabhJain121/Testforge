## 1. How does the current reflection or repair loop work?

In [`testforge/orchestrator.py:1313-1420`](file:///Users/sourabh/TestForge/testforge/orchestrator.py#L1313):
- The loop runs across iterations: `for iteration in range(start_iteration, self.state.max_iterations + 1):`.
- In **Iteration 1**: Initial baseline tests are already generated (Step 1) and validated on clean code (Step 2). Mutants are generated by `ASTMutator.mutate()` and evaluated in parallel isolated sandboxes by `TestExecutionAgent.evaluate_mutants()` (or `sandbox.evaluate_mutants_parallel`).
- If target mutation score is not met, in **Step F** ([`orchestrator.py:1680`](file:///Users/sourabh/TestForge/testforge/orchestrator.py#L1680)), `MutationQualityCriticAgent` is invoked via `A2ABroker.send_message(action="evaluate_quality")`. It classifies killed vs survived mutants, runs `TestQualityAnalyzer` on assertion quality, produces prescriptive directives, and updates `CriticSpace`.
- In **Iteration > 1** ([`orchestrator.py:1320-1397`](file:///Users/sourabh/TestForge/testforge/orchestrator.py#L1320)):
  1. If `critic_directive` and `surviving_mutant_diffs` exist, the orchestrator requests test generation from `GoogleADKTestGenerator` via A2A (`action="generate_tests"`), passing existing test code, surviving diffs, and critic directives.
  2. Candidate test code is validated using `sandbox.validate_and_filter_candidate_suite()` ([`testforge/sandbox.py:430`](file:///Users/sourabh/TestForge/testforge/sandbox.py#L430)).
  3. If retained valid tests exist, `self.state.current_test_code` and `SuiteSpace` are updated. If all candidate tests fail or break clean code, the previous working test suite is preserved.
  4. Mutants are re-evaluated, scores re-calculated, and the loop repeats until target score is reached, max iterations reached, or cancellation requested.

## 2. Where are critic directives stored?

- **Blackboard `CriticSpace` Partition** ([`testforge/blackboard.py:93-112`](file:///Users/sourabh/TestForge/testforge/blackboard.py#L93)):
  - `critic_directives: List[str]` (accumulated historical directives).
  - `latest_directive: str` (sanitized primary directive from the most recent critique).
  - `failure_mechanisms: Dict[str, str]` (mapping of mutant IDs to root-cause failure mechanisms).
  - `semantic_guidance: List[Dict[str, Any]]` (behavioral distinctions).
  - `assertion_quality_findings: List[Dict[str, Any]]` (weak/tautological assertions).
  - `recommended_improvements: List[Dict[str, Any]]` (actionable boundary improvements).
  - `should_iterate: bool` (decision flag from critic).
  - `overall_verdict: str` ("ACTIONABLE" or "SATISFIED").
- **Orchestrator In-Memory State:**
  - `critic_directive: Optional[str]` local loop variable.
  - `self.state.reflection_notes: List[str]`.
  - `self.state.surviving_guidance: List[Dict[str, Any]]`.

## 3. How are surviving mutants and failed tests represented?

- **Mutants:**
  - Represented as `MutantRecord` objects ([`testforge/mutator.py:30-70`](file:///Users/sourabh/TestForge/testforge/mutator.py#L30)) with attributes: `mutant_id`, `mutation_type`, `line_number`, `original_code_snippet`, `mutated_code_snippet`, `unified_diff`, `status` ("KILLED", "SURVIVED", "TIMEOUT", "SYNTAX_ERROR", "EQUIVALENT", "POTENTIALLY_EQUIVALENT").
  - Partitioned in `MutantSpace.mutants` and mirrored in `self.state.mutants`.
  - Surviving unified diffs are stored in `MutantSpace.surviving_mutant_diffs` and `self.state.surviving_mutant_diffs`.
- **Failed Tests:**
  - Represented in `TestExecutionPayload` ([`testforge/a2a.py:289`](file:///Users/sourabh/TestForge/testforge/a2a.py#L289)) as `failures` (list of dicts containing `test_id`, `error_message`, `traceback`) and `quarantined_tests: List[str]`.
  - Stored in Blackboard `ExecutionSpace.failures` and `ExecutionSpace.quarantined_tests`.
  - In `GranularTestValidator` ([`testforge/sandbox.py:475`](file:///Users/sourabh/TestForge/testforge/sandbox.py#L475)), individual test outcomes are categorized as `valid_tests`, `failing_tests`, `inconclusive_tests`, or `trivial_tests`.

## 4. How does the existing generator receive critic recommendations?

- **Direct Method Call:** `GoogleADKTestGenerator.generate_tests()` ([`testforge/adk_generator.py:374-450`](file:///Users/sourabh/TestForge/testforge/adk_generator.py#L374)) accepts:
  - `critic_directive: Optional[str]`
  - `surviving_diffs: Optional[List[str]]`
  - `surviving_mutants: Optional[List[Any]]`
  - `existing_test_code: Optional[str]`
  - `test_plan: Optional[Any]`
  It sanitizes the directive via `sanitize_critic_directive()` and formats it within a passive `<untrusted_content>` block to prevent prompt injection propagation.
- **In-Process A2A Protocol:** Via `A2AMessage` sent to `agent:google-adk:generator` with `action="generate_tests"` and payload matching `A2ATestGenerationRequestPayload` ([`testforge/a2a.py:191`](file:///Users/sourabh/TestForge/testforge/a2a.py#L191)).

## 5. How are generated test files updated or replaced?

- In `orchestrator.py:1368-1397`:
  1. Candidate test code from generator is passed to `self.sandbox.validate_and_filter_candidate_suite()`.
  2. The AST validator parses individual `def test_*` functions and runs each against clean code in an isolated subprocess.
  3. If `validation_res.retained_count > 0`: `self.state.current_test_code` is updated with `validation_res.retained_test_code`, and `SuiteSpace` is updated atomically (`current_test_code`, `hardened_test_code`).
  4. If all tests fail: the candidate is discarded, a warning is logged, and the previous accepted suite remains intact in `SuiteSpace`.
  5. The physical test file on disk (`test_module_path`, e.g. `test_target.py`) is written at pipeline conclusion or executed in ephemeral sandbox folders (`tempfile.TemporaryDirectory(prefix="testforge_box_")`).

## 6. How are previous test-suite versions and hashes tracked?

- **Blackboard `SuiteSpace`:** Tracks `baseline_test_code`, `candidate_test_code`, `current_test_code`, and `hardened_test_code`.
- **Hashes:** `MutationQualityCriticPayload` ([`testforge/a2a.py:387`](file:///Users/sourabh/TestForge/testforge/a2a.py#L387)) tracks SHA-256 hashes: `source_sha` and `test_sha`.
- **Iteration Metrics History:** Blackboard `MetricsSpace.history` appends `IterationMetrics` ([`testforge/state.py:427`](file:///Users/sourabh/TestForge/testforge/state.py#L427)) on every iteration with `iteration`, `total_mutants`, `killed_mutants`, `survived_mutants`, `mutation_score`, `raw_mutation_score`, `adjusted_mutation_score`, and `line_coverage_pct`.
- **Persistent SQLite Checkpointing:** `SQLiteBlackboardStorage` ([`testforge/persistence.py:177`](file:///Users/sourabh/TestForge/testforge/persistence.py#L177)) stores point-in-time `BlackboardSnapshot`s indexed by `checkpoint_id`, `job_id`, `revision`, and `created_at`.

## 7. How are iteration limits and cancellation handled?

- **Iteration Limits:** Controlled by `self.state.max_iterations` (default 3, passed via orchestrator). When `iteration == self.state.max_iterations`, the loop breaks with `final_hardening_status = "TARGET_SCORE_UNREACHED"` (if below target) or `"MAX_ITERATIONS_REACHED"`.
- **Target Convergence:** If `adj_score >= self.state.target_mutation_score`, sets `final_hardening_status = "SUCCESS"` and terminates immediately.
- **Cancellation / Timeout:**
  - `orchestrator.check_cancellation_or_timeout()` checks `cancel_event.is_set()` and `deadline` at every major lifecycle boundary.
  - If triggered, raises `HardeningCancelledError` or sets `final_hardening_status = "CANCELLED"`.

## 9. Warning Analysis (Phase 4 -> Phase 5: +71 Warnings Investigation)

- **Empirical Observation:**
  - Phase 4: 696 passed, 354 warnings.
  - Phase 5: 710 passed, 425 warnings (+71 warnings).
- **Root Cause Identified:**
  The 71 new warnings are internal CrewAI library `DeprecationWarning`s originating from `crewai/agent/core.py`, `crewai/crew.py`, and `crewai/crews/utils.py` (specifically: `function_calling_llm is deprecated`, `allow_code_execution is deprecated`, `multimodal is deprecated`).
  In Phase 5, we added 14 new tests (`tests/test_mutation_quality_critic_agent.py` [11 tests] and `tests/test_phase5_workflow_integration.py` [3 tests]), which instantiate `crewai.Agent` and `crewai.Crew`. Each instantiation produces ~5 internal library deprecation warnings on Python 3.13.
- **Verdict:** None of these warnings represent defects, resource leaks, or runtime errors in TestForge code. They are third-party framework deprecation notices scheduled for future CrewAI releases. No code suppression is required.
