## 1. Executive Summary

A primary root cause for high mutant survival in Phase 1 was **pseudo-oracle assertions**. The fallback test generator previously emitted tests asserting only `assert res is not None`. Such assertions verify only that the function returned without crashing, allowing arithmetic mutations (`*` $\rightarrow$ `/`), constant replacements (`100` $\rightarrow$ `0`), and logic alterations to survive completely undetected.

In Phase 2, `IntelligentASTSynthesizer` introduces **Value-Aware Assertion Synthesis**. Utilizing an isolated `ReferenceExecutor`, the synthesizer evaluates candidate inputs against the unmutated reference code and synthesizes precise, mathematically tight assertion oracles.

---

## 2. Assertion Quality Taxonomy

The assertion synthesizer classifies outputs into strict Python types:

| Return Type | Old Invariant Pattern | Phase 2 Value-Aware Pattern | Mutation Discriminating Power |
|---|---|---|---|
| **Float** | `assert result is not None` | `assert result == pytest.approx(expected, rel=1e-3)` | High (kills rounding, scaling, arithmetic flips) |
| **Integer** | `assert result is not None` | `assert result == expected` | Maximum (kills off-by-one, constant swaps) |
| **Boolean** | `assert result is not None` | `assert result is True` / `assert result is False` | Maximum (kills invert condition, swap operators) |
| **String** | `assert result is not None` | `assert result == 'expected_val'` | Maximum (kills string truncations, casing bugs) |
| **Dictionary** | `assert result is not None` | Key-value checks: `assert result['status'] == 'PROCESSED'` and `assert result['final_total'] == pytest.approx(...)` | High (kills field omissions and calculation errors) |
| **Exception** | *(not generated)* | `with pytest.raises(ValueError): func(...)` | Maximum (kills missing guards, unhandled inputs) |

## 4. Code Comparison: Before vs. After

### Before (Phase 1 Baseline Assertion)
```python
# Generated during Live Demo / Phase 1
def test_generic_calculate_item_discount():
    res = calculate_item_discount(10.0, 10, "REGULAR")
    assert res is not None  # Survives almost every mutant!
```

### After (Phase 2 Intelligent Value-Aware Assertions)
```python
# Generated by IntelligentASTSynthesizer in Phase 2
def test_calculate_item_discount_nominal():
    result = calculate_item_discount(100.0, 2, 'REGULAR')
    assert result == pytest.approx(0.0, rel=1e-3)

def test_calculate_item_discount_threshold_quantity_50():
    result = calculate_item_discount(100.0, 50, 'REGULAR')
    assert result == pytest.approx(0.15, rel=1e-3)

def test_calculate_item_discount_invalid_unit_price_raises_ValueError():
    with pytest.raises(ValueError):
        calculate_item_discount(0.0, 2, 'REGULAR')

def test_validate_tracking_number_valid_modulo7():
    result = validate_tracking_number('TRK-EXP-123456-4')
    assert result is True

def test_validate_tracking_number_invalid_check_digit():
    result = validate_tracking_number('TRK-EXP-123456-5')
    assert result is False
```

### Assertion Robustness Verdict
Zero tests in Phase 2 use invariant assertions. 100% of generated assertions check concrete deterministic values, direct approximations, or explicit exceptions. This elimination of invariant assertion debt is the primary driver of the mutation score improvement from **3.10% to 68.22%**.
