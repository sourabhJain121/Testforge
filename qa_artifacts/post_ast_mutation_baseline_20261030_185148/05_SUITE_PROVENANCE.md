## 1. Provenance Verification Objective

The integrity of autonomous test generation systems requires rigorous provenance:
1. Every line of generated test code evaluated against mutants must originate directly from the agentic generator (`ADKModelBridge` / `GeneratorAgent`).
2. Candidate test code must be quarantined in `SuiteSpace.candidate_test_code` and pass isolated sandbox validation prior to promotion.
3. The promoted test code (`SuiteSpace.current_test_code`) must cryptographically match the runtime state evaluated against the mutant pool.
4. Exported test artifacts must correspond exactly to the evaluated in-memory test code, with only deterministic environment path preambles added.
5. No manual editing, out-of-band manipulation, or artificial score inflation occurred.

## 3. Sandboxing & Quarantine Verification

The sandbox execution mechanism operates as follows:

```
[Candidate Code in Memory]
         │
         ▼
[Write to /tmp/tmp_sandbox_*/test_candidate.py]
         │
         ▼
[Execute pytest in isolated Subprocess]
         │
    ┌────┴────┐
    │         │
[Passed]   [Failed]
    │         │
    ▼         ▼
[Promote to   [Quarantine /
SuiteSpace]    Reject Candidate]
```

- In both experiments, sandbox execution returned `passed=True, failed=0`.
- The candidate code was directly promoted to `current_test_code`.
- The exact promoted code was evaluated against all 19 mutants (`discount.py`) and 258 mutants (`uploaded_logistics_engine.py`).
- Exported files on disk are generated via `orchestrator.export_hardened_suite()`, which prepends `sys.path.insert(0, os.path.abspath('.'))` so the test can be run standalone from anywhere in the repository. The test function definitions and assertions match `current_test_code` byte-for-byte.
