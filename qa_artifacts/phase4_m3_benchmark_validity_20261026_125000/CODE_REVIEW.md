## 1. Summary of Changes

The changes address audit finding H-01 where broken candidate test suites that failed on clean reference code were falsely credited with 100% mutant kills.

### Key Diff Highlights

1. **`testforge/sandbox.py` (`evaluate_mutants_parallel`)**:
   - Added early rejection check:
     ```python
     if not baseline_passed:
         for m in executable_mutants:
             m.status = "ERROR"
             m.kill_reason = "Baseline clean test suite failed; cannot evaluate or kill mutants."
         return
     ```
   - Added empty test code check:
     ```python
     if not test_code or not test_code.strip():
         for m in executable_mutants:
             m.status = "SURVIVED"
             m.kill_reason = "No test assertions provided; mutant survives by default."
         return
     ```
   - Rationale: Guarantees that no mutant can ever be evaluated or counted as killed when the baseline clean suite fails or when no tests exist.

2. **`testforge/corpus/runner.py` (`_execute_strategy_run`)**:
   - Candidate suites for all three strategies (`baseline`, `zeroshot`, `agentic_reflection`) are now validated via `runner.validate_and_filter_candidate_suite`.
   - Failing candidate tests are quarantined, preventing false-positive kills while retaining valid assertions.
   - Verified that `baseline_passed` is explicitly computed from candidate retention and clean reference test execution.
   - `evaluate_mutants_parallel` is explicitly passed `baseline_passed=baseline_passed` and `test_code_to_eval if baseline_passed else ""`.
   - Defect variants are evaluated only when `baseline_passed is True`.

3. **`tests/test_mutation_guided_repair.py`**:
   - Added 6 deterministic unit tests under `TestBenchmarkValidityAndCleanReferenceValidation`:
     - `test_pass_original_fail_mutant_counts_as_kill`
     - `test_fail_original_and_fail_mutant_does_not_count_as_kill`
     - `test_mixture_valid_and_false_positive_retains_valid_only`
     - `test_clean_reference_timeout_or_error_does_not_count_as_kill`
     - `test_empty_or_fully_rejected_suite_produces_zero_score`
     - `test_all_strategies_use_comparable_validation_rules`

## 3. Potential Risks & Mitigations

- **Risk:** Candidate test suites generated by LLMs with low syntax adherence might have all tests rejected, resulting in 0% mutation score.  
  **Mitigation:** This is the intended mathematical behavior. An invalid test suite that fails on clean code must yield 0% kills, not an artificial 100%. The agentic reflection strategy leverages surviving mutants and compiler error feedback to generate valid tests in subsequent passes.

- **Risk:** Runtime increase from running granular validation on candidate suites.  
  **Mitigation:** Granular validation executes candidate tests in small isolated batches. Since early baseline rejection skips the hundreds of mutant evaluations when tests fail, total benchmark runtime is actually optimized.
