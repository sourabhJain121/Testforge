## 1. Problem Statement & Audit Finding H-01

During the Phase 4.1.2 Independent Acceptance Audit, critical audit finding **H-01** was identified in `testforge/corpus/runner.py`:

> **Finding H-01 (High Severity - Evaluation Integrity):**  
> Candidate test suites generated by LLMs were evaluated directly against mutants without first filtering out tests that fail on clean reference code. Furthermore, `evaluate_mutants_parallel` defaulted to `baseline_passed=True`. When a candidate test suite failed on the original, unmodified reference program (e.g., 7 syntax/import/assertion errors on `task_state_transition`), pytest returned exit code 1 (FAIL) on every single mutant execution. Consequently, all mutants were falsely recorded as `KILLED`, producing an artificial 100% mutation score from a broken test suite.

This inverted the foundational principle of mutation testing: **a mutant kill is only valid if the test passes on the clean reference program and fails on the mutant.**

---

## 2. Root Cause Analysis

Tracing the execution flow in `testforge/corpus/runner.py` and `testforge/sandbox.py`:

1. **Unfiltered Candidate Suite:** In `_execute_strategy_run`, the raw synthesized code (`synth` or `synth_v1`) was assigned directly to `test_code_to_eval`. Although reference run metrics (`tests_failed_on_reference`, `tests_passed_on_reference`) were logged, `test_code_to_eval` was never purged of failing tests.
2. **Implicit Baseline Assumption:** `evaluate_mutants_parallel` in `testforge/sandbox.py` defined `baseline_passed: bool = True` as an optional parameter. In `runner.py`, `evaluate_mutants_parallel(test_code_to_eval, mutants)` was invoked without specifying `baseline_passed`, allowing the default `True` to stand even when the clean reference check had failed.
3. **Flawed Mutation Kill Accounting:** In `_eval_single_mutant`, when `res.status == "FAIL"` and `baseline_passed` was assumed `True`, the mutant was marked `m.status = "KILLED"`. A broken candidate suite with 1 failing assertion therefore "killed" every mutant regardless of whether the mutant was actually affected by the assertion.
4. **Agentic Reflection Loop Contamination:** In `agentic_reflection`, pass 0 candidate tests were evaluated against mutants without granular filtering. Broken pass 0 tests resulted in false kills during intermediate passes, misleading the Critic and Repair agents with invalid semantic guidance.

---

## 3. Architecture & Implementation of the Fix

The fix was designed with surgical precision to ensure mathematical and empirical validity across all strategies (`baseline`, `zeroshot`, `agentic_reflection`) without altering scoring formulas or disrupting the production repair workflow:

### A. Strict Baseline Contract in `testforge/sandbox.py`
In `testforge/sandbox.py`:
- `evaluate_mutants_parallel(test_code, mutants, baseline_passed=True)` was updated to strictly enforce baseline integrity:
  1. If `baseline_passed is False`: No subprocess workers are dispatched. All executable mutants are immediately classified with:
     ```python
     m.status = "ERROR"
     m.kill_reason = "Baseline clean test suite failed; cannot evaluate or kill mutants."
     ```
  2. If `not test_code or not test_code.strip()`: Subprocess workers are skipped, and all executable mutants are classified as:
     ```python
     m.status = "SURVIVED"
     m.kill_reason = "No test assertions provided; mutant survives by default."
     ```
  3. When `baseline_passed is True` and valid test code is supplied, mutants are evaluated via parallel worker processes. Kills are counted if and only if `res.status == "FAIL"` on the mutant.

### B. Granular Candidate Filtering in `testforge/corpus/runner.py`
In `testforge/corpus/runner.py`:
- **Granular Test Validator Integration:** All strategies now invoke `runner.validate_and_filter_candidate_suite(candidate_code, fixture.source_code)`. This parses individual test functions via AST, executes each test against the clean reference code in `SubprocessSandbox`, and:
  - Retains tests that pass cleanly on the reference program (`is_valid=True`).
  - Quarantines tests that fail on clean reference code (`is_valid=False`, false positives).
- **Strategy Pipeline Integration:**
  - **`baseline` Strategy:** Filters fixture baseline test code, guaranteeing that broken baseline tests (if any) cannot produce false kills.
  - **`zeroshot` Strategy:** Filters raw synthesized tests, retaining only genuine clean-passing tests before any mutant evaluation.
  - **`agentic_reflection` Strategy:**
    - Pass 0: Synthesized test suite is filtered immediately. Only clean-passing tests are used to discover surviving mutants and generate semantic guidance.
    - Pass 1: Generated repair tests are validated against clean reference code and merged with pass 0 valid tests via `existing_test_code`.
- **Explicit Clean Reference Verification:**
  - An independent verification check is executed on the final retained test suite against the reference source code.
  - If the verification fails, times out, or encounters a collection error, `baseline_passed` is set to `False`.
  - If `retained_candidates == 0` or candidate test code is empty, `baseline_passed` is set to `False`.
- **Explicit Parameter Passing:**
  - `evaluate_mutants_parallel` is called with explicit `baseline_passed=baseline_passed` and `test_code_to_eval if baseline_passed else ""`.
  - Defect variants are evaluated only when `baseline_passed is True`; otherwise, defect detection is 0.0%.
